# הגשר (Bridge Connector)

שירות Node.js קטן (בלי תלויות חיצוניות) שיושב בין האפליקציה בטלפון לבין הפורום:

- **קבלת פעולות** – `POST /actions`: תגובה, לייק או פתיחת דיון, חתומים מהאפליקציה. הגשר בודק חתימה, מונע כפילויות לפי המזהה הקבוע (`Idempotency-Key` / `jobId`), ומפרסם דרך המתאם.
- **מקור הודעות** – `GET /candidates?account=…`: הודעות חדשות שלא טופלו, עם עומק השרשור (`threadReplies`, `participants`), האם ענו לי ישירות (`directReply`) וכמה תשובות של אחרים יש באמצע (`interveningReplies`). מזה האפליקציה מחליטה על התיוג.
- **חשבונות** – `GET /accounts`: רשימת החשבונות (עסקי / אישי…) לבחירה מהאפליקציה. כל חשבון עם עוגייה/טוקן משלו.

> חשוב: הבוט נבדק ורץ מול **פורום הבדיקה** בלבד. בפרוג עצמו אסור להפעיל בוטים.

## הפעלה מהירה (פורום מדומה, בלי שום חשבון)

```
cd bridge
BRIDGE_SECRET=סוד-ארוך ADAPTER=memory node server.js
```

בווינדוס (PowerShell):

```
cd bridge
$env:BRIDGE_SECRET="סוד-ארוך"; $env:ADAPTER="memory"; node server.js
```

הגשר עולה על פורט 8787. בפורום המדומה יש נקודות קצה להדגמה: `POST /dev/seed`, `POST /dev/post`, `GET /dev/forum`.

## חיבור האפליקציה

בלשונית "הגדרות" ← "תכנון יומי וביצוע אוטומטי":

1. כתובת היעד: `https://<הגשר>/actions`
2. סוד לחתימה: אותו `BRIDGE_SECRET`
3. טוקן גישה: אותו `BRIDGE_TOKEN` (אם הגדרת)
4. מקור הודעות: `https://<הגשר>/candidates`
5. "בדיקת חיבור ליעד" ← צריך לקבל "היעד ענה (HTTP 200)".
6. "טען חשבונות מהגשר" ← לבחור את החשבון. אפשר להחליף אחר כך בלחיצה בלשונית "ראשי".

## חיבור לפורום אמיתי (פורום הבדיקה)

ב־`.env` (ראו `.env.example`):

- `ADAPTER=rest` ו־`FORUM_API_BASE=https://…/api`
- לכל חשבון: `AUTH_TOKEN` ו/או `SESSION_COOKIE` (לחשבון הראשון), ו־`AUTH_TOKEN_PERSONAL` / `SESSION_COOKIE_PERSONAL` לחשבון `personal` וכן הלאה.
- הסודות נמצאים **רק** במשתני סביבה. קובץ החשבונות (`accounts.json`) מכיל רק שמות, ואף פעם לא עוגיות.
- עוגייה שהפורום מחדש (`Set-Cookie`) נשמרת אוטומטית לכל חשבון.
- הסשן פג (401/403) ← הפעולה לא מתפרסמת, מסומנת ככישלון קבוע, ומגיע מייל לבעלים לחדש את העוגייה/הטוקן.

אם לפורום אין API של JSON, כותבים מתאם משלך: קובץ עם המחלקה (`fetchNew`, `reply`, `like`, `openThread`, `checkSession`), ומפעילים `ADAPTER=./my-adapter.js`. הליבה לא משתנה. החוזה המלא כתוב בראש `src/adapter.js`.

## מה עוד הגשר נותן לאפליקציה

- `GET /threads/:id?account=` – השרשור המלא לתצוגת השיח (מי כתב מה, התגובות שלי, ציטוטים). במתאם REST: `FORUM_EP_POSTS` (ברירת מחדל `/threads/{threadId}/posts`).
- `GET /search?account=&from=&to=&q=&author=&mine=1` – חיפוש הודעות לצ'אט האישי (במתאם REST: `FORUM_EP_SEARCH`).
- `GET /config` – לאיזה פורום הגשר מחובר, איזה מתאם ואילו חשבונות (בלי סודות). האפליקציה מציגה את זה ב"בדיקת חיבור לפורום".
- כל הודעה ב־`/candidates` מגיעה עם `context` – עד 6 ההודעות שלפניה.

## כללים שהגשר אוכף

- **חתימה**: בלי `x-prog-signature` נכונה ← 401.
- **כפילויות**: אותה פעולה פעמיים ← אותה תשובה (`duplicate:true`) בלי לפרסם שוב. שומר את זה גם אחרי הפעלה מחדש.
- **תקלה זמנית** בפורום ← 503 / 429 (עם `Retry-After`), והטלפון מנסה שוב. **דחייה** ← 4xx קבוע.
- **חשבון אחד לכל שרשור**: חשבון אחד כבר כתב בשרשור ← השני לא כותב בו (409). כיבוי: `ONE_ACCOUNT_PER_THREAD=off`.
- **כמה הודעות בשרשור**: חוזרות כל ההודעות שלא טופלו (בתוך שרשור מהחדשה לישנה), כל אחת עם `newerReplies`. מצב מצומצם – רק האחרונה: `LATEST_PER_THREAD=on`.
- **מענה להודעה ספציפית**: תגובה עם `replyToPostId` מתפרסמת כמענה להודעה הזאת, ועם `quote` – כציטוט שלה (במקום @ בטקסט). הודעה שלא קיימת ← 404.
